# Desktop design review: remaining screens (clothes.localhost:5173, owner, Neha Fashion test shop)

Method: live viewing in the built-in browser at 1366x768 and 1920x1080, plus DOM text and width checks. "Source" for every finding below is direct observation (live app, 2026-11-06). Nothing was saved. Two items were added to the bill cart and then removed.

## How do the remaining screens hold up at desktop width, and what should change?

### Takeaway
At >=1024px the sidebar shell works, but almost every screen except #/bill is still a single phone column stretched to the full content width (main area is about 1152px wide at 1366, and wider at 1920). Short rows end up with a label at the far left and a number at the far right, empty space everywhere, and forms with full-width inputs. Reports, ledgers and lists need real desktop layouts (tables, list+detail). Settings and forms only need a max-width and a 2-column grid.

### Cited Findings (all from live observation)

Shared shell issues
- Content width: `main` measured 1152px wide at 1366 on khata, inbox, cashbook, expenses, settings/staff, stocktake and items/pick, so cards stretch edge to edge. #/pnl (~962px) and the reports (~1110-1126px) use slightly narrower but still very wide columns. Severity: High. Fix: wrap non-table pages in `max-w-3xl mx-auto` (forms/settings) or `max-w-6xl` (reports), and use the extra width for multi-column grids, not for stretching.
- Header: the green top bar still shows a mobile back arrow "‹" next to the shop name on sub-pages (dues, reports, gst, cashbook, settings, suppliers…) even though the sidebar is visible. There is no page title or breadcrumb, so the user cannot tell which screen they are on. Severity: Medium. Fix: on lg, replace the back arrow with a page title (H1) and, for sub-pages, a breadcrumb (Reports › Sizes). Put page actions (Add customer, Export) in the header on the right.
- Sidebar: it shows only Home, Khata, Bill, Orders, Items. Reports, Dues, P&L, GST, Cashbook, Expenses, Suppliers, Stocktake and Settings have no entries, so desktop users must go through Home. Severity: High. Fix: add a "Money" group (Dues, Cashbook, Expenses, P&L, GST) and a "Shop" group (Reports, Stocktake, Suppliers, Settings) to the sidebar on lg only. The mobile bottom nav stays as it is.
- Floating action button: "+ ग्राहक जोड़ें" sits as a FAB at the bottom right of a 1366px screen. Severity: Low-Medium. Fix: on lg, show it as a header button.
- Bottom sheets: the size/colour picker on #/bill opens as a bottom sheet (~240px wide, anchored to the bottom of the screen) at 1920 width. Severity: Medium. Fix: on lg, show it as a centred dialog or as a popover anchored to the tile.
- Route lag: right after a hash change, screenshots taken within about 2s often still showed the previous screen. For example, #/stocktake briefly showed the staff page and #/expenses briefly showed cashbook content. Text checks after 3.5s showed the correct screens. Possible cause: slow lazy-loading with no loading state, so stale content stays on screen. Severity: Medium (perceived bug). Fix: clear old content or show a skeleton straight away on route change.

### Inferences
- Priority order for dedicated desktop pages: Khata (list+detail ledger), Reports suite (dashboard + tables), Cashbook, P&L, Items pick, Orders. Settings/staff/suppliers come next, and GST/stocktake/expenses need only small changes.
- A shared `<DesktopTable>` component and `<ListDetail>` layout would cover about 10 of the 17 screens.
- A global rule "non-table pages max-w-3xl centred on lg" would fix most of the stretching issues in one change.

### Gaps
- The test shop has no customers and no orders, so the customer ledger (#/khata/:id) and the order detail screen could not be opened or reviewed. A shop with seeded data (for example kirana.localhost) should be checked.
- 1920x1080 was only screenshotted for #/reports/sizes and #/bill. Other screens were inferred to stretch the same way, based on the full-width containers measured at 1366.
- Charts on #/reports were seen only partly (one bar visible above the fold).
